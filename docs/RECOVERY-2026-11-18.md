# 2026-11-18 recovery incident and release gate

## Confirmed observations

- The installed 1.5.0 process was still alive when inspected on November 18.
  Sampling showed a responsive main run loop, and URL diagnostics returned.
  No BarButler crash report was present. This does not invalidate the user's
  report of an unavailable or apparently terminated app.
- The pusher was separated from the toggle by icons that should have been hidden.
  Diagnostics showed `collapsed=true`, `adjacent=false`, and `repair paused`.
- Repeated pusher-only re-anchoring failed. The repair counter had reached 52.
  The first retained failure was at 15:46 on November 17 (UTC+08:00); later
  failures persisted through display/system sleep and wake. The initiating
  trigger has **not** been reproduced or established.
- The old repair callback completed even when geometry remained invalid.
  Delayed repairs could overlap or survive a system transition, and the sliding
  retry window restarted failed attempts every ten minutes.

## Containment

- Preserved process samples, diagnostics, the 1.5.0 bundle and current preferences
  locally before stopping the affected process. These user-specific files are
  deliberately **not** checked into the repository.
- Restored the previously signed 1.4.1 application without importing an older
  preferences snapshot. Layout pins, toggle position, click mode, collapsed
  preference, icon style and collapse delay were compared and retained.
- Temporarily disabled automatic checks/downloads on the recovered installation
  to prevent an immediate upgrade loop.
- Restored the public appcast to signed 1.4.1. Retained 1.5.0 as a prerelease with
  a warning rather than deleting its tag or rewriting published history.
- Confirmed the recovered application's diagnostics, hidden-item geometry,
  Settings on reopen, and a clean quit/relaunch. This is a service recovery,
  **not** proof that 1.4.1 can never suffer a related geometry failure.

## Candidate changes (unreleased)

1. A single bounded transaction owns each divider repair. Each stage is checked
   after AppKit has time to settle; concurrent requests join the same transaction.
2. If saved-position and geometry-based pusher replacement both fail, rebuild
   only our toggle and pusher at the known-good position. Never reset third-party
   positions or saved icon sections as a repair strategy.
3. Explicit outcomes distinguish recovered, failed and cancelled. Do not claim
   recovery or collapse against an unverified boundary on a failed operation.
4. System generations invalidate stale callbacks; display sleep, session loss
   and screen lock suspend work as well as full system sleep.
5. Exhausted attempts remain paused until a genuine settle or explicit manual
   retry. Layout recording and icon moves do not overlap anchor replacement.
6. Simultaneous launches elect the oldest live instance; duplicate launches ask
   that instance to show Settings instead of silently quitting with no feedback.

## Automated checks

`bash scripts/test.sh` runs the same regression methods using XCTest under full
Xcode, or the assertion adapter with Command Line Tools. Recovery tests use an
injected deterministic scheduler; they do **not** move real menu-bar items or
claim to emulate WindowServer or actual sleep.

Coverage includes ignored position writes, verified escalation, all-stage
failure, joined requests, cancellation, obsolete callbacks after restart,
system-generation changes, bounded retries, and deterministic instance election.
Existing single-item policy, keyboard, shortcut and event-field tests remain.

## Required before another stable release

- [ ] Reproduce and capture the initiating geometry failure, or explicitly
      identify any remaining unknown trigger in candidate release notes.
- [ ] Test a packaged candidate on Intel and Apple Silicon. Verify cold launch,
      overlapping launches, Finder reopen, clean quit and relaunch.
- [ ] Verify real pusher displacement and both position-replacement failures;
      confirm the own-anchor rebuild restores the boundary without changing
      remembered sections or the user's toggle location.
- [ ] Exercise display sleep/wake, full sleep/wake, lock/unlock and display
      configuration changes, including a transition between every repair stage.
- [ ] Repeat transitions during a single-item menu and during icon restoration.
      Check that no unrelated hidden icon becomes visible during panel clicks.
- [ ] Extended/overnight runtime with diagnostics: no repeating failed repair
      loop, stuck synthetic input, growing event-tap count or lost reopen response.
- [ ] Compare preferences and saved layout before/after; verify signatures and
      the signed update artifact. Publish only then; do not replace the recovered
      installation just because unit tests or a short smoke test pass.

The local installation intentionally remains 1.4.1 while these gates are open.
